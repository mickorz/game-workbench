# 知识库 01：游戏资源复用技巧（改 FGUI 前先读这条）

> 用途：**告诉我（和任何改这个工程的人）在动手前先想复用，别动不动就出新图。**
> 口径来源：`fgui文档/00-核心流程总纲.md`（最高优先级）。事实来源：本工程实测（`facts.json` / 组件 XML / `package.xml` / 工程自带的 FGUI API 参考），**不靠通用传说**。
> 记录时间：2026-09-23

## 〇、一条铁律

> **除了需求明确要求新增的图片，其他一律先找现有资源复用。**
> 复用手段：**调整大小 · 九宫拉伸 · 旋转 · 倾斜 · 镜像 · 改颜色 · 改透明度 · 变灰 · 叠文字 · 用现成组件**。
> 上面这些都不行，**才**走 AI 生图（那时才需要写生图规格：尺寸/透明底/九宫格/命名）。

## 一、手段速查表（全部有工程真实用例）

| 手段 | FGUI 里怎么设 | 工程真实用例（实测） | 什么时候用 | 坑 |
|---|---|---|---|---|
| **等比缩放** | 节点 `scale="0.8,0.8"`；运行期 `SetScale` | `comboSefl.xml` 复用 `mahHandSelf.xml` 缩到 `0.8,0.8` 当碰杠牌 | 同一张图要大、小两版 | 缩小到 <0.5 会糊；放大会糊（**底板/头像放大就是这种情况**） |
| **非等比拉伸** | 改 `size="w,h"` **＋ 把 `fill` 设成 `scaleFree`** | 底板 `n2`：`size="1618,175"`、**没写 fill** | 纯渐变/纯色底、边框简单的图 | ⚠ **只改 size 不写 `fill` 可能不拉伸**（见下面第三节）；圆角/花纹会被拉扁 |
| **九宫格** | `package.xml`：`<image scale="9grid" scale9grid="左,上,右,下"/>` | `9_box_lsxq.png` = `29,25,3,11`；`9_img_duogang_bg.png` = `10,34,20,68`；`ImgFanxingBgNs.png` = `114,14,6,138`；`img_emotion_down.png` = `72,13,12,12` | 面板/底板/气泡要变宽变高 | 边界改错会切到花纹；**改的是包的资源登记，所有用它的界面一起变** |
| **旋转** | `rotation="1"`（单位：度，可小数）；gearLook 第 2 个字段 | `ResultItem.xml` 的胡标 `n26`：`rotation="1"`（微倾 1°）；`mahHandSelf.xml` 的 gearLook `1,90,0,0 / 1,270,0,0`（左右家的牌转 90°/270°） | 微倾做视觉、座位方向复用同一张牌 | 旋转要配 `pivot="0.5,0.5" anchor="true"`，否则绕左上角转、位置会飞 |
| **3D 倾斜** | `rotationX` / `rotationY` / `skew`（FGUI 的 `GObject` 支持） | 工程**暂无用例** | 立体感、透视 | 工程没先例，先在编辑器里试再定 |
| **镜像翻转** | `scale="-1,1"` | `XxxMahBackView.xml` 的 `Back2`：`scale="-1,1"` 复用同一张桌面图做右侧 | 左右对称的装饰 | 带方向性的图案会反（字、箭头） |
| **改颜色（染色）** | loader `color`；文字 `color`；**`gearColor`**（按控制器页换色） | `FlowItem.xml` 的 gearColor：`C_WinLost` 页 1 = `#849ac3`，默认 = `#f0d268` —— **同一套流水条，赢/输两种颜色** | 赢/输、正常/禁用两版 | 染色是乘算，深底/暗图上染不出亮色 |
| **变灰** | `grayed="true"`；或 gearLook 第 3 个字段 | gearLook `values="1,0,0,0"` 第 3 位 = 变灰开关（工程里都是 0） | 未解锁、不可点 | 变灰不影响点击，要配 `touchable` |
| **改透明度** | `alpha`（0~1）；或 gearLook **第 1 个字段** | gearLook `default="1,90,0,0"` 第 1 位恒为 1 | 蒙层、弱化次要信息 | 别用 `alpha=0` 代替隐藏（还占点击、耗性能）→ 用 `visible` |
| **裁剪 / 填充模式** | loader `fill` 取值（见第二节）+ `fillAmount/fillMethod` | 工程用过：`scaleFree` 8 处、`none` 3 处、`scaleNoBorder` 3 处、`scale` 1 处 | 进度条、按需裁切 | `fill` 是**缩放模式**，不是裁切；圆头像得用遮罩/组件 |
| **叠文字代替出图** | 图只做底，字用 `text` 节点 | 现有标签 = 底 `img_biaoqian.png` + 成品图；文字节点用法见 `KW_Score`、`KW_Nickname`、`KW_TEXT_ROOMTIME` | 文案可能改、字数少 | 要自己排版（对齐/换行/字号自适应 `autoSize="shrink"`） |
| **用现成组件** | 直接引用 `ui://组件` | `comboSefl`（碰杠组）、`mahHandSelf`（手牌，含正面/扣着/立着/赖子角标）、`Button9Scale`（九宫按钮）、`FlowItem`（流水条） | 同类元素已存在 | **改这些组件＝影响所有引用它的界面**（用 `lookup.py` 查引用） |

## 二、`fill` 的 6 个取值（工程自带 `editor.d.ts` 口径）

```
None = 0            不缩放（按原图尺寸画）
Scale = 1           等比缩放（整图缩到框内）
ScaleMatchHeight = 2 等比＋以高度为准
ScaleMatchWidth = 3  等比＋以宽度为准
ScaleFree = 4        非等比拉伸填满（＝把图拉扁/拉长）
ScaleNoBorder = 5    等比铺满（超出裁掉）
```

**要"把底板拉高"就用 `ScaleFree`（`fill="scaleFree"`）；用 `Scale`（等比）改高度会变成不变形、留空。**

## 三、两个特别容易踩的坑（本工程实测）

1. **只改 `size` 不一定拉伸**：`ResultItem.xml` 的底板 `n2` 是 `size="1618,175"` 且**没有 `fill` 属性**（工程 19 个 loader 里有 15 个显式写了 fill，所以"不写"就是走编辑器默认值，不可依赖）。
   → **做法：把节点的 `fill` 显式设成 `scaleFree`，再改高度。** 不放心就在 FGUI 编辑器里看"填充处理"那一栏确认。
2. **同名图分在两个包**：`img_bs_zhuang.png` 在 `xxx_mah_result` 和 `xxx_mah_common` 里各有一份（记得两份都要管，或确认只动一份是不是有意的）。
3. **九宫格在包里，不在组件里**：`scale9grid` 写在 `package.xml` 的 `<image>` 上，改它＝改所有引用这张图的界面。组件 XML 里搜不到 `scale9grid` 是正常的。

## 新建包的包 id 必须正好 8 位（`ui://` 按 8 位切分）

**想达成什么**：新建一个包（`assets/<包名>/package.xml`）之后，编辑器里能正常双击打开里面的组件、能出预览。

| 手段 | FGUI 里怎么设 | 工程真实用例 | 坑 |
|---|---|---|---|
| 包 id | `packageDescription id="..."` —— **正好 8 位** | 工程原有 7 个包全部 8 位：`i23bcf06`/`izz1xup7`/`xmahcomm`/`n3dx31ny`/`xmahpiao`/`xmahplyr`/`ul5y9sqy`；编辑器自带工程 7 个包也全部 8 位（`nk9ejx23`/`1joxvsss`/…） | **写成 10 位（如 `xmahxuanzi`）→ 编辑器里双击没有任何反应、预览空白、控制台一条报错都没有** |

**为什么**：FGUI 的资源地址是 `ui://` + **前 8 位＝包 id** + **后面＝资源 id**（工程内 52 处 `ui://` 引用无一例外都按 8 位切分）。
包 id 超长时，`ui://xmahxuanzixz001` 会被当成"包 `xmahxuan`（不存在）+ 资源 `zixz001`"→ 查不到就**静默什么都不做**（不是崩溃，所以没有异常、没有日志）。

**自检**：
- 包 id 长度 =8；
- 组件里每个 `ui://` 的前 8 位都等于某个真实包 id、后面的部分必须是那个包里已登记的资源 id（两个条件同时成立才打得开）。

**注意**：包 id 与**文件夹名**是两回事（文件夹仍叫 `xxx_mah_xuanzi`）；改的是 `package.xml` 里的 id 以及所有 `ui://` 引用（改 id 之后，凡引用过这个包的地址都要同步改）。

## 四、每次复用前必查 3 件事（防连带事故）

| 查什么 | 怎么查 | 为什么 |
|---|---|---|
| 这张图/这个组件被谁引用 | `python .opencode/skills/fgui-flow/scripts/lookup.py <关键词>`（读 `facts.json` 的 usage） | 共用资源一改，别的界面跟着变 |
| 有没有九宫格 | `package.xml` 里搜 `scale9grid` | 有九宫格的图**别改图**，改节点尺寸就行 |
| 有没有同名图/同名组件分在多处 | `lookup.py` + `工程结构.md` | 改一份不会同步另一份 |

## 五、决策顺序（成本从低到高，逐级往下走）

1. **改现有节点的尺寸/位置/颜色/透明度** —— 0 新图
2. **九宫格拉伸**（先确认这张图有没有 `scale9grid`）—— 0 新图
3. **非等比拉伸 / 缩放 / 镜像 / 旋转 / 变色**（`fill="scaleFree"`、`scale`、`rotation`、`gearColor`）—— 0 新图
4. **换一张已有的相似图**（`美术资源清单.md` 里还有没人用的图，例如 `ico_gui.png`）—— 0 新图
5. **复用现成的通用件（组件）** —— 0 新图。**控件类需求（按钮 / 弹层 / 头像 / 手牌 / 流水条）优先走这一级，别在需求自己的包里再造一个长得一样的组件。** 清单与用法见下面「通用件优先复用」那一节
6. **用文字节点顶掉图**（文案类内容一律优先文字）—— 0 新图
7. **以上都不行 → 才 AI 生图** —— 这时才写规格（尺寸 / 透明底 / 九宫格 / 命名＝最终文件名 / 风格参考）

## 通用件优先复用（本工程现成的通用按钮 / 控件清单）

**想达成什么**：需求里出现"按钮""弹层底""头像""手牌""流水条"这类**工程里已经有通用件**的元素时，
**先引用通用件、只覆盖差异属性**，而不是在需求自己的包里再做一个长得一样的组件。

**为什么优先级高**：通用件已经把**交互**一起给了（控制器页值、按下反馈、`gearDisplay`/`gearSize`），
自己造的只会有外观、行为还得重配 —— 而且以后改样式要改两处。

### 通用按钮 `Button9Scale`（`xbb002`）★ 最常复用

| 项 | 值 |
|---|---|
| 在哪 | `xxx_mah_result/component/Button9Scale.xml`（组件 id **`xbb002`**，包 id `ul5y9sqy`，画布 100×20、`pivot="0.5,0.5"`、`extention="Button"`） |
| 怎么引用 | **同包**：`src="xbb002" fileName="component/Button9Scale.xml"`；**跨包**：**还要加 `pkg="ul5y9sqy"`**（见下面"坑 ②"） |
| 实例怎么覆盖 | `<Button icon="ui://<包id><图资源id>" title="按钮字" titleColor="#226999" titleFontSize="38"/>` —— 全都在**实例**上写，不用改组件 |
| 白拿什么 | 底图（`icon`，`fill="scaleFree"`+relation 跟尺寸 → **给 `size` 就自动铺满**）、居中文字（`title` relation `center-center,middle-middle`）、**按下反馈**（`<Button downEffect="scale" downEffectValue="1.1"/>`）、控制器 `button`（0 up / 1 down / 2 over / 3 selectedOver） |
| 能覆盖什么尺寸 | 工程现有引用从 **36×39 到 248×86** 都有（见下表），所以"任意宽高的一块底图 + 一行居中字"都吃得下 |

**工程真实用例（实测，2026-09-28）**：

| 文件::节点 | size | 覆盖了什么 |
|---|---|---|
| `xxx_mah_result/component/MainResultLayer.xml::KW_BTN_GOON` | 223,81 | `title="继续游戏" titleColor="#175a3a" **titleFontSize="36"** icon="ui://ul5y9sqyfj701n"` ← **改字号的唯一范式** |
| `MainResultLayer.xml::KW_PRESS_SHOW` | 155,78 | `touchable="false"`（当纯视觉壳用） |
| `MainResultLayer.xml::KW_BTN_LASTMAHS` | 69,80 | 只给 `icon`（无文字） |
| `MainResultLayer.xml::KW_BTN_CLOSE` / `::KW_BTN_HUDUN` / `::KW_BTN_FENXIANG` | 86,85 / 70,70 / 70,70 | 小方按钮 |
| `xxx_mah_result/component/ResultItem.xml::KW_Click_Flow` / `::KW_Click_Head` | 36,39 / 120,120 | 当**点击热区**用（可以完全没图） |
| `assets/xxx_mah_liangdao/XxxMahLiangDaoView.xml::KW_BTN_Cancel` | 248,86 | 跨包复用（亮倒UI 的"取消"）：`pkg="ul5y9sqy"` + 换 `icon` |

**坑**：

1. **组件里 `title` 写死 12 号白字**（`fontSize="12" color="#ffffff"`），字号与字色**只能靠实例**的 `titleFontSize` / `titleColor` 覆盖。
   照 `KW_BTN_GOON` 写就对了（那条已上线）。
2. **跨包引用必须 `pkg="<8位包id>"`，否则静默失效**：不带 `pkg` 时，编辑器/加载器只在本包里找 `src`，
   找不到就**什么都不做**（不报错、不崩溃）。工程先例：`xxx_mah_player/XxxMahPlayerView.xml` 的 4 个
   `playerHead` 节点写的都是 `src="l3g66" fileName="component/playerHead.xml" pkg="xmahcomm"`。
3. **跨包引用的目标资源必须勾「导出」**（`package.xml` 里 `exported="true"`）。
   **实测（2026-09-28）**：`Button9Scale.xml` 原本**没勾**，跨包引用它需要在 `xxx_mah_result/package.xml`
   给 `xbb002` 补上 `exported="true"` —— 需求方在编辑器里勾上之后才成立。
   编辑器插件 API 也印证这条口径：`DependencyQuery.SeekLevel { SELECTION=0, SAME_PACKAGE_BUT_NOT_EXPORTED=1, SAME_PACKAGE=2, ALL=3 }`
   —— 查依赖时的搜索范围里，"本包"和"本包但没导出"是**两个不同层级**，往外才到 `ALL`。
4. **名字里的 "9Scale" 会误导**：它的底图**不走九宫格**，而是 `fill="scaleFree"` 非等比拉伸
   （工程给它配的 `BtnGreen01.png` / `bnt_syp.png` 都是普通图，没有 `scale9grid`）。
   所以**圆角/花纹多的底图拉大拉扁会变形**；这种图要拉伸就得自己在 `package.xml` 上配 `scale9grid`。
5. **改它＝改所有引用它的界面**（现在 **9 处**）。复用请只在实例上覆盖，**不要改组件本身**（先 `lookup.py Button9Scale`）。

## 六、反例（别这么做）

- 因为"字不一样"就重新生一张标签图 → 先看能不能「复用底图 + 文字节点叠字」。
- 因为"高度差一点"就重画底板 → 先看 `fill="scaleFree"` 拉伸或九宫格。
- 直接改共用图去迁就某一个界面 → 会连带改到其他界面（先查引用）。
- 用 `alpha=0` 当隐藏 → 用 `visible="false"`。
- 缩放超过 ~1.2 倍硬顶 → 图会糊，这种情况才值得出新图。

## 八、以后怎么往知识库里加东西（写作约定）

**加文件**：`.opencode/knowledge/<序号>-<主题>.md`（如 `02-列表与行距.md`）→ 自动被 `knowledge.py` 扫到，不用改任何技能。

**加条目**：在文件里加一个 `##` 小节 —— 检索是按**小节**做的（`--topic` 只匹配 `##` 及更深的标题，不会把整份文件倒出来）。

一条好条目的写法（照抄这个结构，检索和复用都最省事）：

```markdown
## <主题词出现在标题里，便于按主题检索>

**想达成什么**：一句话。

| 手段 | FGUI 里怎么设 | 工程真实用例（哪个文件哪个节点） | 坑 |
|---|---|---|---|
| … | … | … | … |

**注意**：只在"工程实测过"的前提下写"工程真实用例"；没实测的写"工程暂无先例，用前先在编辑器确认"。
```

**约定**：
1. **标题里点明关键词**（"九宫格""拉伸""旋转""染色"…），否则 `--topic` 找不到；
2. **一切结论带出处**：实测的写 `文件::节点/属性`，来自工程自带文档的写文件名（如 `editor.d.ts`），推断的标注"推断"；
3. **不要写具体某个需求的数值**（那是"方案"的事）—— 知识库只放可复用的手法与坑；
4. 同一条手法只在一处维护；发现矛盾以**后写且实测过**的为准，并删掉旧说法。
