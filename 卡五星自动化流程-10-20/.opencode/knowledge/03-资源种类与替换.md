# 资源"种类"与替换（先定种类，再谈出图）

> 一句话：**动工之前先把每个要产出的资源的"种类"和"规格"写死**。
> 种类定错＝返工；种类＋规格定死，替换就是"同名同规格覆盖"，**节点一行都不用改**。
> 这张表顺带就是**生图 / 出字体的方向单**（人照着做、AI 照着生成）。

## 一、为什么"种类"比"画得好不好"更早要定

占位阶段常见的三种错（每一种都要返工）：

| 错法 | 后果 |
|---|---|
| 把**位图字体**该做的事，做成一张**图片** | 数字是变的（漂1/漂2/漂12），做成图片就得按数量出 N 张、还要配控制器换图；字体只要拼字符 |
| 把**九宫格**该做的事，做成**普通图** | 面板一拉伸就变形；回头补 `scale9grid` 还得重新登记 |
| 把**能复用现成**的东西，做成新图 | 白出一张图，还多一份登记，将来两边不同步 |

**结论**：种类是"结构决定"，画面才是"美术决定"。先把结构定死，美术什么时候来都不影响工程。

## 二、本工程有哪些"种类"（怎么一眼认出来）

| 种类 | 认法（工程里的痕迹） | 规格必须写死 |
|---|---|---|
| **图片** | `package.xml` 里 `<image id=… name=… path="/atlas/">` | 尺寸（px）、是否透明底（RGBA）、放在哪个目录 |
| **九宫格图** | 同一个 `<image>` 上带 `scale="9grid" scale9grid="左,上,右,下"` | 尺寸 + **四边边界**（边界写错＝拉伸时角变形） |
| **非等比拉伸的图** | 节点上带 `fill="scaleFree"`（如本题的底板 `n2`） | 原图尺寸 + 目标尺寸（横纵拉伸倍数不一样，画面要能接受） |
| **位图字体＋字形** | `package.xml` 里 `<font id=… name="x.fnt" path="/fnt/">`，字形在 `fnt/<字体名>/<字符>.png` | **字形高（全字体统一）**、字符表（哪些字符映射到哪个字形）、`.fnt` 里 `info size=`、放在哪个目录 |
| **组件** | `package.xml` 里 `<component … exported="...">` | 只登记，不产出图 |
| **复用现成** | 引用已有资源 id / 已有字形 / 改颜色·透明度·镜像·旋转 | 写清"复用哪个 id、怎么改的" |

> 位图字体的文件结构（照 `win.fnt` / `lose.fnt` 抄）：
> `<包>/fnt/<字体名>.fnt` ＋ `<包>/fnt/<字体名>/<字符>.png`；
> `.fnt` 内容极简，每行一个字符：
> ```
> info size=32 colored=false
> char id=48 img=<资源id> xoffset=0 yoffset=0 xadvance=0
> ```
> `id` 是字符的 Unicode 码（`'0'`=48 … `'9'`=57）；**成词的字形用 ASCII 字母占位**是这套字体的惯例
> （如 `win.fnt` 的 `f` ＝一张「(封顶)」的图、`lose.fnt` 的 `p` ＝「(破产)」）。

## 四、用法一：替换时**不许改节点**

占位和真品必须**同规格**，否则替换还是要动工程：

- 图片：占位就是最终尺寸（`placeholder_png.py --size` 写的就是最终尺寸）。
- 字体：**占位字形的尺寸（尤其"高"）要和真字形一致** —— 节点上挂的 `scale` 是按"字形高"算出来的；
  真字形高变了，画面大小就变了，还得回去改 `scale`。
- 名字：占位文件名**就是最终文件名**（＝槽位名），不要"占位叫 tmp_、真图叫正式名"。

换句话说：**替换动作应该只有"覆盖同名文件"这一下。**

## 五、用法二：这张表就是"生图 / 出字体"的方向单

给 AI 生图或给人出字体时，直接从表里搬字段：

- **图片**：尺寸 / 透明底 / 是否九宫格（含边界）/ 数量（几张、分别什么状态）/ 命名（＝最终文件名）/ 风格参照（截图或同屏已有图）。
- **位图字体**：要包含哪些字符、**字形高**、每个字形对应哪个字符、`.fnt` 的 `size`、目录结构、颜色是否 `colored`。
- 顺带提醒：**AI 写中文容易出错字**；文案可能变的，优先"底图 + 文字节点叠字"，别把字烤进图里。

## 六、本需求的两个实例（一眼看懂两种玩法）

| 需求 | 种类怎么定的 | 结果 |
|---|---|---|
| 头像右上角【漂X】 | **位图字体**（不是图片、也不是普通文字，因为要显示"漂1/漂2/漂12"这种可变组合） | 开了 `fnt/piao.fnt` 槽位＋11 个占位字形；节点挂字体 + `scale`；程序拼字符 `p2`＝「漂2」。真字体来了**同名覆盖，节点不用动** |
| 总得分旁的【封顶】 | **复用现成**（工程位图字体里本来就有「(封顶)」字形） | 撤掉独立标识节点＋那张新图；程序把字形拼进得分文本即可 |

> 反例（踩过的坑）：先按要求做了一张「封顶」标识图，后来才发现 `win.fnt` 里早就有这个字形 —— **先查"有没有现成的、是不是另一种种类"，再决定出不出图。**

## 七、自检清单（交付前过一遍）

1. 每个新资源都能说出**种类**吗？种类是"结构上必须这样"，还是"随手选了一个"？
2. **最终文件名＝槽位名**吗？规格（尺寸/边距/字形高/字符表/目录）都写了吗？
3. 真东西到手**只用覆盖同名文件**，工程**不用改**吗？
4. 表里的字段**够不够直接拿去生图/出字体**？（给 AI 或给人不需要再问第二遍）
5. 有没有"本该复用现成"却被我做成新资源？（尤其**字形**：先翻 `fnt/*/*.png` 和现有图片名）
