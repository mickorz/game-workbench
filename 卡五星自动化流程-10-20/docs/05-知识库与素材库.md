# 05 · 知识库与素材库

## 1. 三套「事实」别搞混

| 名称 | 位置 | 是什么 | 谁维护 |
|---|---|---|---|
| **事实底座** | `.opencode/work/facts.json`、`工程结构.md`、`美术资源清单.md` | 扫描 FGUI 工程得到的节点/资源/结构事实 | `scan_fgui.py` 自动生成 |
| **知识库** | `.opencode/knowledge/*.md` | 复用、排版、资源种类、PSD 规范等经验 | 人维护，持续更新 |
| **PSD 素材库** | `.opencode/PSD素材库/` | 可复用源 PSD + 索引 + 预览图 | 美术维护，s4 只读消费 |

定位节点/资源用**事实底座**；判断「怎么做/要不要新图/怎么排」用**知识库**；找可复用 PSD 用**素材库**。

## 2. 事实底座

### 2.1 什么时候扫

- 第一次使用；
- FGUI 工程被改过（编辑器保存、别人提交、你自己 s2 改完）；
- `lookup.py --check` 说过期。

### 2.2 命令

```powershell
python .opencode/skills/fgui-flow/scripts/scan_fgui.py
python .opencode/skills/fgui-flow/scripts/lookup.py --check
```

产物（project 级，落在 `.opencode/work/` 顶层）：

```
.opencode/work/
├─ facts.json            机器读的事实表
├─ 工程结构.md            人读的工程结构
├─ 美术资源清单.md         人读的资源清单
└─ 美术清单.备注.txt       人工补的中文说明（<关键词> = <说明>）
```

### 2.3 纪律

- **不要手改** `facts.json` / `工程结构.md` / `美术资源清单.md`。
- 节点名、坐标、资源 id、图片尺寸**只用实测事实**，不凭记忆。
- `lookup.py` 只读；定位优先用它，不要为了一个小查询全量重扫。

## 3. 动态知识库

### 3.1 位置与文件

唯一一份：`.opencode/knowledge/`

当前包含：

| 文件 | 主题 |
|---|---|
| `01-资源复用技巧.md` | 复用手段、`fill` 取值、通用件、决策顺序、反例 |
| `02-对齐与成组.md` | 分组、居中、垂直对齐、留白/间距、右对齐/锚点 |
| `03-资源种类与替换.md` | 资源种类表、替换不改节点、生图/出字体方向单 |
| `psd-art-spec.md` | PSD 画布、图层命名/标签、九宫格、蒙版、文字、GList、Z-Order |

> 文件会持续增加/修改。**不要凭记忆引用，也不要把内容抄进技能或方案**。

### 3.2 怎么查

```powershell
# 索引：文件 + 标题树（★主题词从这里来）
python .opencode/skills/fgui-flow/scripts/knowledge.py --list

# 按主题取相关小节，可多次
python .opencode/skills/fgui-flow/scripts/knowledge.py --topic 复用 --topic 九宫格
python .opencode/skills/fgui-flow/scripts/knowledge.py --topic 对齐 --topic 留白

# 取整份文件（按文件名片段匹配）
python .opencode/skills/fgui-flow/scripts/knowledge.py --path 复用技巧

# 自检
python .opencode/skills/fgui-flow/scripts/knowledge.py --check
```

**主题词以当次 `--list` 的标题为准**。技能/文档里写的 `--topic 复用` 只是例子，不是全集。

### 3.3 什么时候必须查

- 判断「这个效果该用哪种手法」；
- 判断「要不要出新图 / 要不要新建组件」；
- **改坐标、排位置、定间距之前**（排版类：对齐 / 成组 / 留白 / 间距 / 居中 / 锚点）；
- s3 生成 PSD 之前（`psd-art-spec.md` 是硬规范）。

### 3.4 怎么往知识库里加东西

1. 在 `.opencode/knowledge/` 新建或编辑 `.md`；
2. 用 `#` 写文件标题，用 `##` 写**可检索的主题**（`--topic` 主要从 `##` 标题提取）；
3. 一个小节只讲一件事，标题尽量用使用者会搜的词；
4. 写清「适用场景 / 做法 / 反例 / 工程实例」；
5. 不要写一次性需求细节，写可复用的手法；
6. 加完跑一次：

```powershell
python .opencode/skills/fgui-flow/scripts/knowledge.py --list
python .opencode/skills/fgui-flow/scripts/knowledge.py --topic <新主题>
```

### 3.5 维护原则

- 知识库是**唯一来源**；技能、命令、agent 里只写「去查知识库」，不复制内容。
- 发现新坑，直接补知识库；不要只留在聊天记录里。
- 知识库内容变了，不需要改脚本；`knowledge.py` 每次实时读文件。

## 4. PSD 素材库

### 4.1 定位

s4 的可复用源 PSD 库。**运行态只读**：`find-asset` 检索 `index.json` 和 `_预览/`，命中后把 PSD 复制到需求目录再改，绝不改原件。

路径配置在 `workspace.json` 的 `素材库根`，默认 `.opencode\PSD素材库`。

### 4.2 目录结构

```
.opencode/PSD素材库/
├─ index.json            全局索引（build_index.py 维护）
├─ build_index.py        本地维护脚本副本
├─ README.md             素材库说明
├─ 按钮/
│  ├─ 按钮.psd
│  └─ _预览/             该分类的透明缩略图
├─ 标签/
│  ├─ 标签.psd
│  └─ _预览/
├─ 文字/
│  ├─ 文字.psd
│  └─ _预览/
├─ 面板/ 图标/ ...
└─ _原稿/                未整理/暂存区（索引跳过）
```

### 4.3 怎么加新素材

1. **规范图层组结构**：
   - 最外层组（制作单元）＝完整组件，如 `按钮-蓝`；
   - 嵌套子组（底图组）＝纯背景/形状，如圆角矩形、光效；
   - 组名清晰，便于匹配。
2. **放进分类目录**（未整理先放 `_原稿/`）。
3. **刷新索引与预览**：

```powershell
python .opencode/skills/psd-style/scripts/build_index.py `
  --lib ".opencode/PSD素材库" --write --preview
```

该命令会解析制作单元/嵌套底图/文本层，导出分类 `_预览/` 缩略图，并刷新 `index.json`。

### 4.4 s4 怎么消费

```powershell
python .opencode/lib/workspace.py find-asset <需求> [--id R1] [--top 3]
```

候选会列出：

- 最外层制作单元；
- 嵌套底图组；
- 分类独享预览图路径（`分类/_预览/*.png`）。

**人要先比对参考图外观再确认**。未命中就保留占位、报「待 AI 生图」，不报错。

### 4.5 分享与降级

- 素材库**不绑定具体工程**，可整包拷给别人；对方把 `素材库根` 指过来即可。
- 没有素材库也能跑：`find-asset` 未命中就全部走占位。
- 不要为了匹配而重建别人机器上的索引；索引由素材库维护者刷新。

## 5. 三者之间的边界

| 操作 | 事实底座 | 知识库 | 素材库 |
|---|---|---|---|
| 读 | ✅ `lookup.py` | ✅ `knowledge.py` | ✅ `find-asset` |
| 写 | 只由 `scan_fgui.py` 写 | 人工编辑 | 人工加 PSD + `build_index.py` |
| s2 改工程时 | 只读 | 现读 | 可查候选（最终以 s4 为准） |
| s3 出 PSD 时 | 只读 | 必须对照 `psd-art-spec.md` | 不直接消费 |
| s4 切图时 | 只读 | 现读 | **只读消费**，改动写需求副本 |
