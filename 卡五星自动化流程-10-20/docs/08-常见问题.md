# 08 · 常见问题

## 1. 命令 / agent / 技能

### 斜杠命令不出现

- 确认 opencode 是在**含 `.opencode` 的那层**启动的；
- 确认 `.opencode/command/*.md` 存在；
- 改过配置/命令/技能后**重启 opencode**；
- 命令名是文件名：`s0-env.md` → `/s0-env`。

### agent 列表里没有 `fgui-flow`

- 确认 `.opencode/agent/fgui-flow.md` 存在；
- 检查 frontmatter 的 `mode: primary` 是否被改坏；
- 重启 opencode。

### 技能没被加载 / 模型不按技能走

- 命令文件应该用 `skill` 工具显式加载对应技能；
- 直接说「按 s2 流程做」时，agent 应先确认做哪一步，再加载技能；
- 如果模型跳步，直接指定：`/s2-fgui <需求>`，并提醒它先读 `SKILL.md`。

## 2. 工作区与工程定位

### `找不到工作区根`

命令要在**含 `.opencode` 的目录**执行。脚本本身会向上找；如果还是失败，用：

```powershell
python .opencode/lib/workspace.py --root "<工作区根>" where
```

或给具体脚本加 `--root`。

### `/s0-env` 报 `client_code_root` 不存在

本机没有 `xc_spce_info.json` 里写的 `.xflow` 路径。两种处理：

```powershell
# 临时显式指定
python .opencode/lib/workspace.py env --client "<真实 FGUI 工程根>"

# 或修改 xc_spce_info.json 的 project_info.client_code_root
```

### `where` 没有 `client_dir`

还没跑 s0。先：

```powershell
python .opencode/lib/workspace.py env
```

### 定位到了错误的工程

- 检查 `game_id` 与 `game_key` 是否匹配；
- 真实工程根必须同时有 `assets/`、`settings/`、`*.fairy`；
- `assets/` 下必须有以 `game_key` 为前缀的包；
- 用 `env --client` 显式指定，避免自动定位猜错。

## 3. 事实底座 / 定位

### `lookup.py --check` 报过期

工程被改过。重扫：

```powershell
python .opencode/skills/fgui-flow/scripts/scan_fgui.py
```

### `lookup.py` 没命中

- 换关键词，或先用 `--comp <组件名> --nodes` 看全节点；
- 确认不是拼写/大小写问题；
- 确认事实底座不是过期状态；
- 中文备注可在 `.opencode/work/美术清单.备注.txt` 里补。

### 事实底座文件能手改吗

不能。`facts.json`、`工程结构.md`、`美术资源清单.md` 是扫描产物；改工程后重扫。人工说明写到 `美术清单.备注.txt`。

## 4. s1 解析需求

### `excel_to_req.py` 报缺少 openpyxl

```powershell
python -m pip install openpyxl
```

### Excel 读不到行 / 列名识别不对

- 确认表头含「名称」「描述」等关键词；
- 确认是 `.xlsx`，不是旧的 `.xls`；
- 一个 Excel 多行 = 多个需求，每行必须有名称；
- 识别不了时，手工建 `<需求>/需求.md` 兜底（表头至少含名称/描述）。

### `check_terms.py` 退出码 4

表示有需要人工确认的项，不是脚本坏了。把结论写进 `施工单.md` 第一节，再继续。

### `parse_requirement.py` 报缺名称/描述

需求 md 里必须有表头含「名称」+「描述」的表；按报错行号补。

### 参考图适配失败

- 需要 Pillow：`python -m pip install pillow`；
- 确认 `--out` 指向需求目录（含 `参考图/`）；
- 默认画布 1334×750，可用 `--canvas WxH` 改。

## 5. s2 改工程

### 模型想跳过 s1 直接改工程

正确做法：先有 `<需求>/清单.json` + `施工单.md`。没有就回到 `/s1-req`，不要手抄截图。

### 找不到节点 / 坐标不对

- 先 `lookup.py --check`；
- 过期就 `scan_fgui.py`；
- 用 `lookup.py --comp <组件名> --nodes` 看全节点；
- 不凭记忆写坐标。

### 要不要出新图

先过复用 7 级：

```
改尺寸/位置/颜色/透明度 → 九宫格 → 非等比拉伸/旋转/镜像/变色
→ 换相似图 → 复用通用件 → 文字节点顶图 → 才 AI 生图
```

判断看**需求结构**，不是看名字。多状态卡牌这类通用件没有的结构，单独建，不要硬套。提新图必须给全规格。

### 占位图覆盖了已有文件

`placeholder_png.py` 默认不覆盖已存在文件；需要覆盖时加 `--force`。占位图要同名同规格落到 `<需求>/占位/` 和 client 工程 `assets/<包>/atlas/`。

### 落位后模型继续写文档

不应该。闸门通过、效果定稿**之前**只改工程文件；确认后再一次性补校验报告/修改清单/交付说明/`psd-spec.json`。

## 6. s3 出 PSD

### `_fgui_layout.py` 退出码 2

表示有告警（不支持的 gear/relation/节点类型等）。告警在 stderr；**先回来确认怎么处理，不要硬跑**。

### PSD 图层坐标偏移

- 检查 `anchor="true"` 的口径：`xy` 是 pivot 点，不是左上角；
- 检查 `relation` 增量语义；
- 用 `_pc_build.py` 自带的逐层校验结果定位；
- 不要按图层名跨组配对，按 `(父级组, 图层名)` 配。

### 按钮状态没画全

s3 确认阶段要问清控制器状态（如 `C_ZiState`）。前几个按钮分别演示不同状态，其余走默认态；变灰用黑白调整图层，不要改图片像素。

### 文字字体不对

FGUI 的 `font=""` 是运行时默认字体，推不出具体字体。按系统字体近似，或让用户指定。PhotoCraft 直接读 Windows 系统字体。

### `_pc_build.py` 跑很久 / 中途想停

几百个节点会跑几分钟，**不要中途 kill**。批量跑时 kill 会在 PhotoCraft 里留下半成品文档（不影响磁盘 PSD）。先 `--dry-run` 确认计划。

## 7. s4 改样式切图

### 应该改哪个 PSD

源 PSD 三来源：素材库命中 / s3 还原稿 / 用户给。**必须用户确认**。没确认就只问，不遍历目录猜，不拿产物目录里的当输入。

### 改错组（同色按钮一堆）

组名可重复。用 `lyid` 定位：

```powershell
python .opencode/skills/psd-style/scripts/_psd_lfx.py --layers "<psd>"
# 找到 lyid 后
python .opencode/skills/psd-style/scripts/_psd_recolor.py "<psd>" --组lyid 23 --out "<psd>"
```

### 改了颜色但 PNG/画面没变

- 确认改的是图层效果本身，不是被别的效果盖住；
- 用 `--inspect` 看 `[开]` / `[关]`；
- 改完必须回存（`_pc_export.py` 默认回存）；只改文字属性不回存，画面不会变。

### 导出 0 张图

目标图层/组没有 `out_` 前缀。用：

```powershell
python .opencode/skills/psd-style/scripts/_rename_layer.py "<psd>" - out_xxx --lyid 23 --out "<psd>"
```

或 `_psd_clone.py` / `_psd_group_clone.py` 生成带 `out_` 的副本。

### 导出的图尺寸不一致 / 内容没居中

用 `_fit_frames.py` 统一：

```powershell
python .opencode/skills/psd-style/scripts/_fit_frames.py "<需求>/切图" --size 240x60
```

### 8 张图内容完全一样

`--texts` 没生效，或图层不是文字层。确认：

- 目标图层带 `out_` 前缀；
- 是 TySh 文字层，不是栅格化图层；
- `--texts` JSON 的 key 与图层名一致。

### 切图回写工程后没变化

定稿后要跑：

```powershell
python .opencode/lib/workspace.py place <需求>
```

它把 `<需求>/切图/` 同名回写 `FGUI/` 快照和 client 工程根。确认文件名就是槽位名。

## 8. PhotoCraft / MCP

### `photocraft.py --check` 失败

按顺序查：

1. `photocraft.exe` 路径（`photocraft.json` 的 `exe` 或 `PHOTOCRAFT_EXE`）；
2. token 文件是否存在、与桌面端是否同一个；
3. 端口 7878 是否被别的实例占用；
4. 桌面端读写根是否覆盖输入/输出。

详细排查表见 `06-PhotoCraft与MCP配置.md` 第 7 节。

### MCP 工具不出现

- `opencode.json` 的 JSON 是否合法；
- `command[0]` 是否是 `photocraft-cli.exe` 的完整路径；
- `--bridge` 端口与桌面端 `--control` 是否一致；
- `--control-token-file` 是否同一个文件；
- 改完是否重启 opencode。

### MCP 连不上 / `the request was not sent`

- MCP bridge **不会自动拉起桌面端**，先手动启动 PhotoCraft；
- 确认端口、token；
- 长任务用 `wait:false` + `jobs_list`，不要死等。

### `automation read/write ... failed`

桌面端的 `--automation-read-root` / `--automation-write-root` 没覆盖目标路径。放宽根并重启桌面端。注意：这两个参数是**桌面端**的，不是 MCP CLI 的。

### 换端口

桌面端和 MCP/Python 配置都要改：

- `--control <新端口>`
- MCP `--bridge 127.0.0.1:<新端口>`
- `photocraft.json` 的 `port`

## 9. 路径、编码、权限

### 中文乱码

脚本内部已 UTF-8。PowerShell 控制台可能显示乱码：

```powershell
chcp 65001
[Console]::OutputEncoding=[System.Text.Encoding]::UTF8
```

文件本身用编辑器看是正常的即可。

### 路径有空格或中文

PowerShell 里用引号 + 调用运算符：

```powershell
& "D:\带 空格\photocraft.exe" --control 7878
```

### 路径过长 / 权限不足

- 尽量把工作区放在较短路径下；
- 不要放在需要管理员权限的目录；
- 不要放在同步盘（OneDrive 等）里跑大量文件操作。

## 10. 多需求 / 批次

- s1 可以一次从 Excel 生成多个需求目录；
- s2/s3/s4 建议按批执行，每批 4 个左右，人确认后继续；
- 每个需求的产物完全独立，靠 `<需求>/清单.json` 交接；
- 不要跨需求复用同一个 `psd/制作/` 副本。

## 11. 还是解决不了

按这个顺序收集信息再问人：

```powershell
python .opencode/lib/workspace.py where
python .opencode/skills/fgui-flow/scripts/lookup.py --check
python .opencode/lib/photocraft.py --check
```

并附上：

- 执行的完整命令；
- 报错原文；
- 需求名 / 工程路径；
- 最近改过什么（工程、配置、脚本、知识库）。
