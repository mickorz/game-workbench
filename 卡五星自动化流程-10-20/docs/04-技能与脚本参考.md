# 04 · 技能与脚本参考

> 本文是**索引**。每个技能的完整步骤、纪律、坑位以对应 `SKILL.md` 为准；脚本参数以 `python <脚本> --help` 为准。

## 1. 技能是怎么被加载的

```
.opencode/skills/<技能名>/SKILL.md
```

frontmatter 至少包含 `name` 和 `description`；opencode 用 `description` 判断何时加载。命令文件和 agent 会用 `skill` 工具显式加载。

| 技能 | 对应步骤 | 一句话 |
|---|---|---|
| `fgui-env` | s0 | 定位 client 工程，写 `workspace.json` |
| `fgui-req` | s1 | Excel / 手工需求 → 清单 + 施工单 |
| `fgui-flow` | s2 | 消费清单/施工单，改 FGUI 工程 |
| `fgui-to-psd` | s3 | 界面 XML → 分层 PSD 还原稿 |
| `psd-style` | s4 | 改 PSD 样式/文字/尺寸，导出切图并回写 |

### 1.1 主 agent：`fgui-flow`

文件：`.opencode/agent/fgui-flow.md`

```yaml
---
description: FairyGUI 美术流程执行者：把策划需求 + 美术需求（截图）按 s0~s4 五步变成 FGUI 工程改动……
mode: primary
---
```

**职责**：

- 开工先用一两句话确认「这次做哪一步」，不默认；
- 加载对应技能（s0 → `fgui-env`，s1 → `fgui-req`，s2 → `fgui-flow`，s3 → `fgui-to-psd`，s4 → `psd-style`）；
- 确定工作区根（含 `.opencode` 的那层），所有命令在这里执行；
- 用 `workspace.py where` 确认 `client_dir`；
- 执行 `AGENTS.md` 的 9 条硬规矩；
- s2 落位后只停一次（效果确认闸门），确认前不写文档；
- 交付后只**提示** s3/s4，不自动做。

**命令文件里的 `agent: fgui-flow`** 就是把这个 agent 绑定到 `/s0-env` ~ `/s4-psd`。新增 agent 时，在 `.opencode/agent/` 放 Markdown + frontmatter（`description`、`mode`）即可。

## 2. `fgui-env`（s0）

**作用**：只做环境定位，不改任何工程文件。

**输入**：`xc_spce_info.json` 的 `client_code_root` / `game_id` / `game_key`，或显式 `--client`。

**输出**：`.opencode/workspace.json` 的 `client_dir`、`game_key`、`game_id`。

**脚本**：无独立脚本，使用共享库：

```powershell
python .opencode/lib/workspace.py env --check
python .opencode/lib/workspace.py env
python .opencode/lib/workspace.py env --client "<真实工程目录>"
python .opencode/lib/workspace.py where
```

**纪律**：

- 只改 `.opencode/`。
- 定位失败列候选、问人，不猜。

## 3. `fgui-req`（s1）

**作用**：把需求变成可施工输入；不碰 FGUI 工程。

**输入**：`inbox/` 里的 Excel，或手工 `需求.md` + `参考图/`。

**输出**：`需求.md`、`参考图*/`、`清单.json`（需求[]）、`清单.md`、`施工单.md`。

**脚本**（`.opencode/skills/fgui-req/scripts/`）：

| 脚本 | 作用 | 常用参数 |
|---|---|---|
| `excel_to_req.py` | Excel → 每行一个需求目录 | `[xlsx]`、`--root`、`--force` |
| `check_terms.py` | 错别字/清单一致性/疑似矛盾 | `files...`、`--terms`、`--json`；**退出码 4 = 有待确认项** |
| `parse_requirement.py` | 解析「一行一需求」进 `清单.json` 的 `需求[]` | `reqmd`、`--out`、`--需求` |
| `refimage_to_canvas.py` | 参考图适配画布（默认 1334×750，纯黑填充居中） | `--out`、`--canvas`、`--src` |
| `build_guide.py` | 生成 `施工单.md` 骨架 | `req`、`--out`、`--force` |

辅助文件：`terms.json`（术语表）、`施工单模板.md`。

**纪律**：

- 只写 `.opencode/`。
- 需求写明的不再问；影响施工且没说的进决定清单，一次问清。
- 不编造语义；拿不准进决定清单。
- 美术需求为准，冲突逐条列出。

## 4. `fgui-flow`（s2）

**作用**：消费 s1 产物，把需求落到 client 工程。

**输入**：`<需求>/清单.json` + `施工单.md`、截图、工程事实底座。

**输出**：改好的组件 XML / `package.xml`、`方案.md`、`备份/`、`占位/`、`FGUI/` 快照、`psd-spec.json`、定稿后的校验报告/修改清单/交付说明。

**脚本**（`.opencode/skills/fgui-flow/scripts/`）：

| 脚本 | 作用 | 常用参数/说明 |
|---|---|---|
| `scan_fgui.py` | 扫描工程，生成事实底座 | `--root`、`--out`、`--json`、`--no-art`、`--no-struct` |
| `lookup.py` | 关键词定位包/组件/节点/资源/备注 | `关键词...`、`--comp X --nodes`、`--check`、`--force`、`--json` |
| `knowledge.py` | 动态读取知识库 | `--list`、`--topic`、`--path`、`--check` |
| `placeholder_png.py` | 生成同规格占位 PNG | `--size`、`--out`、`--label`、`--scale9`、`--force` |
| `generate_psd_spec.py` | 生成 s2→s3 的 `psd-spec.json` | `[需求名]`、`--req-dir`、`--view`、`--root` |

**关键命令**：

```powershell
python .opencode/skills/fgui-flow/scripts/scan_fgui.py
python .opencode/skills/fgui-flow/scripts/lookup.py --check
python .opencode/skills/fgui-flow/scripts/lookup.py <关键词>
python .opencode/skills/fgui-flow/scripts/lookup.py --comp <组件名> --nodes
python .opencode/skills/fgui-flow/scripts/knowledge.py --list
python .opencode/skills/fgui-flow/scripts/knowledge.py --topic 复用 --topic 九宫格
python .opencode/skills/fgui-flow/scripts/placeholder_png.py --size 96,33 --out "<需求>/占位/atlas/img_x.png" --label TAG
python .opencode/skills/fgui-flow/scripts/generate_psd_spec.py <需求> --view <组件XML>
```

**退出码**：

- `lookup.py`：`1` = 事实表缺失/过期（先重扫）；`3` = 组件或关键词没命中。
- `knowledge.py`：`1` = 关键词/文件名没命中；`3` = 知识库目录不存在或为空。
- `check_terms.py`：`0` = 没问题；`4` = 有需要人工确认的项；`1` = 用法/文件错误。
- 其它脚本以实际输出为准。

**纪律**：

- 只改需求涉及的包与组件；不碰 `settings/`、其它包、业务代码。
- 改前备份。
- 事实只用 `lookup.py` / XML 得出。
- 落位后只有一道闸门；确认前不写文档。
- 复用决策 7 级走到底才生图。

## 5. `fgui-to-psd`（s3）

**作用**：把 FGUI 界面还原成可编辑的分层 PSD 还原稿。

**输入**：`<需求>/psd-spec.json`（优先），或界面 XML + 复用件清单。

**输出**：`<需求>/psd/还原稿/*.psd`；中间文件 `_tmp/`。

**脚本**（`.opencode/skills/fgui-to-psd/scripts/`）：

| 脚本 | 作用 | 常用参数 |
|---|---|---|
| `_fgui_layout.py` | 界面 XML → 布局清单 JSON（离线） | `<view.xml>`、`--spec`、`--assets`、`--out`、`--reuse`、`--state-default`、`--state` |
| `_pc_build.py` | 在 PhotoCraft 里搭分层 PSD 并保存 | `<manifest.json>`、`--out`、`--port`、`--dry-run`、`--no-verify` |
| `_psd_layerinfo.py` | 列 PSD 图层结构 | `<psd>` |
| `_psd_struct.py` | PSD 结构字节级自检 | `<psd>` |
| `_psd_lfx.py` | 图层样式/文字/数值检查与修改（与 s4 共用） | 见 `--help` |

**关键命令**：

```powershell
python .opencode/lib/photocraft.py --check

python .opencode/skills/fgui-to-psd/scripts/_fgui_layout.py `
  --spec "<需求>/psd-spec.json" `
  --out "<需求>/_tmp/manifest.json"

python .opencode/skills/fgui-to-psd/scripts/_pc_build.py `
  "<需求>/_tmp/manifest.json" --dry-run

python .opencode/skills/fgui-to-psd/scripts/_pc_build.py `
  "<需求>/_tmp/manifest.json" `
  --out "<需求>/psd/还原稿/<界面名>_还原稿.psd"
```

**退出码**：`_fgui_layout.py` 的 `0` = 无告警，`2` = 有告警（stderr）。**有告警先解决再往下走**。

**边界**：

- 只还原 FGUI 里有的东西；不反推设计。
- 不改 FGUI 工程、不导出切图。
- 不支持的 gear/relation/节点类型会明确告警，不静默算错。

## 6. `psd-style`（s4）

**作用**：在 PSD 上改样式/文字/尺寸，导出透明 PNG，并回写 FGUI 工程。

**输入**：清单 + 源 PSD + 要改什么。源 PSD 必须由用户确认。

**输出**：`<需求>/psd/制作/<槽位名>.psd`、`<需求>/切图/*.png`；`place` 回写快照 + client 工程。

**脚本**（`.opencode/skills/psd-style/scripts/`）：

| 类别 | 脚本 | 作用 |
|---|---|---|
| 查看 | `_psd_lfx.py --layers/--inspect` | 列图层、看图层样式全部属性 |
| 样式 | `_psd_lfx.py --set-color/--set-gradient/--set-num/--set-effect` | 改颜色、渐变、不透明度/角度/大小/距离/扩展、开关效果 |
| 文字 | `_psd_lfx.py --set-text` | 改文字内容（可长可短） |
| 样式库 | `_apply_asl.py` / `_asl_extract.py` | 套 ASL、列出 ASL 样式 |
| 复制 | `_psd_clone.py` | 一个图层复制成 N 个 |
| 组复制 | `_psd_group_clone.py` | 整组复制（含子层/裁切/蒙版） |
| 整组换色 | `_psd_recolor.py` | 栅格位图 + 形状 + 图层效果一起换色 |
| 改尺寸 | `_psd_reshape.py` | 四角半径不动、只拉伸中间（矢量形状 + 栅格映射） |
| 改名 | `_rename_layer.py` | 给目标单元加 `out_` 前缀 |
| 导出 | `_pc_export.py` | 导出 `out_` 图层/组为透明 PNG；默认回存 PSD |
| 统一尺寸 | `_fit_frames.py` | 多张 PNG 统一画布尺寸并居中 |
| 结构自检 | `_psd_struct.py` | 字节级校验 PSD |
| 预览 | `_psd_preview.py` | 生成预览图并打印主要颜色 |
| 底层 | `_psd_raster.py` / `_psd_group.py` / `_psd_tysh.py` | 栅格重采样、组定位/可见性、TySh/EngineData 细节 |
| 素材库 | `build_index.py` | 刷新素材库索引与分类预览 |

**关键命令**：

```powershell
python .opencode/lib/workspace.py find-asset <需求>
python .opencode/skills/psd-style/scripts/_psd_lfx.py --layers "<psd>"
python .opencode/skills/psd-style/scripts/_psd_lfx.py --set-text "<psd>" out_b "新文案" --out "<psd>"
python .opencode/skills/psd-style/scripts/_pc_export.py "<psd>" "<需求>/切图" --canvas 400x160 --texts "<需求>/_tmp/texts.json"
python .opencode/skills/psd-style/scripts/_fit_frames.py "<需求>/切图" --size 240x60
python .opencode/lib/workspace.py place <需求>
```

**纪律**：

- 源 PSD 只读；素材库只读；改动只写需求副本。
- 用户确认前不写任何文件。
- 组名重复用 `lyid` 定位。
- 配色只换算，不做设计。
- 导出前目标单元要带 `out_` 前缀。

## 7. 共享库 `.opencode/lib/`

### 7.1 `workspace.py`

所有技能的路径/清单/快照/素材库入口：

| 子命令 | 作用 | 常用写法 |
|---|---|---|
| `where` | 打印工作区根 / out_root / 素材库根 / client_dir / game_key | `where [--需求 X]` |
| `env` | 定位 client 工程并写 `workspace.json` | `env [--client P] [--check]` |
| `setup` | 修改 `workspace.json` 的路径项 | `setup --out-root ... --素材库根 ... --工程快照范围 packages` |
| `snapshot` | 建工程快照到 `<需求>/FGUI/` | `snapshot <需求> [--packages a,b] [--range packages\|all]` |
| `manifest-init` | 建清单骨架 | `manifest-init <需求> [--force]` |
| `manifest-add` | 加一条资源 | `manifest-add <需求> --槽位名 ... --种类 ... --尺寸 ...` |
| `manifest-set` | 改条目 | `manifest-set <需求> --id R1 --set 来源=...` |
| `manifest-md` | 由 JSON 生成 `清单.md` | `manifest-md <需求>` |
| `需求-add` / `需求-set` | 增改需求条目 | 见 `--help` |
| `find-asset` | 查 PSD 素材库 | `find-asset <需求> [--id R1] [--top 3]` |
| `place` | 切图同名回写快照 + client 工程 | `place <需求> [--id R1]` |

清单字段（`manifest-add --help` 有完整枚举）：

- `种类`：图片 / 九宫格图 / 非等比拉伸 / 位图字体 / 组件 / 复用现成
- `来源`：复用现成 / 工程已有 / 素材库命中 / AI生图 / 占位
- `状态`：待制作 / 占位中 / 已产出 / 已替换
- 其它：`尺寸`、`透明底`、`九宫格`、`字形高`、`字符表`、`用途`、`占位`、`备注`

### 7.2 `photocraft.py`

PhotoCraft 控制协议客户端，s3/s4 的渲染后端：

| 能力 | 说明 |
|---|---|
| `ensure()` | 桌面端没开就自动拉起；返回已认证客户端 |
| `engine(...)` | 执行引擎命令（建文档/建组/置入/建文字等） |
| `open_doc()` / `save_doc()` | 打开 PSD / 保存导出 |
| `request()` | 原始控制协议调用（JSON 行） |

命令行自检：

```powershell
python .opencode/lib/photocraft.py --check
```

配置优先级：**显式参数 > 环境变量 > `.opencode/photocraft.json` > 内建默认**。详见 `06-PhotoCraft与MCP配置.md`。

## 8. 脚本编写约定

- 所有命令在**工作区根**执行；脚本自己向上找 `.opencode` / `*.fairy` + `assets/`，不写死工程名。
- 输出统一 UTF-8（脚本已 `reconfigure`）；控制台乱码用编辑器看文件。
- 不要改 `.opencode/work/facts.json`、`工程结构.md`、`美术资源清单.md` 这些扫描产物；改工程后重扫。
- 新增脚本时优先复用 `.opencode/lib/workspace.py` 和 `photocraft.py`，不要在脚本里重复实现路径定位。
